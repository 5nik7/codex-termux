# codex-termux 0.4.4

This release fixes the recurring `outdated mandoc.db lacks codex-termux(1)`
warning when opening `man codex-termux` on Termux.

The installer keeps each version's manual inside the man directory, where
mandoc can index it. The public manual link still follows the package's single
`current` pointer, so upgrades select the command, completions, and manual
together. Previous payloads, manuals, and recovery backups are retained.

Install, repair, uninstall, and recovery refresh the index when `makewhatis`
is available. Index failures are reported without undoing a completed package
operation; substituted indexes and unfinished index builds are preserved.
Regression tests cover the old warning, same-version repair, upgrades, rollback,
uninstall, unrelated manuals, and index failure handling.

## Upgrade

```bash
codex-termux manage self-update
codex-termux manage self-update --repair
man codex-termux
```

When upgrading through the bundled installer from 0.4.3 or earlier, the first
command installs the new helper; the one-time repair then applies its corrected
manual layout. Both operations ask for confirmation. Fresh installations using
the latest installer already use the fixed layout.

Rebuilding the old index alone cannot resolve the warning.
For a same-version reinstall from a built checkout, use
`bash install.sh --source "$PWD" --repair` and confirm the operation.

Public commands, options, configuration, and forwarding behavior remain
compatible. `manage update` separately manages the Codex npm runtime.

## Validation and assets

See `VALIDATION.md` and `docs/evidence/0.4.4/` in the source bundle for checks,
native Termux evidence, and platform limits. Tests use owned roots and fake
