# codex-termux 0.4.2

This release brings Termux service control and readable terminal reports to
codex-termux, including clean display of Codex logs containing ANSI colors.

## Service management

`manage server` and `connect` now default to the existing `codex-remote` runit
service. Start, stop, restart, and status use Termux `sv` with bounded waits.
Enable/disable control autostart, is-enabled reports its setting, logs reads
existing service logs with rotation following, and check verifies authenticated
loopback connectivity without printing tokens.

Explicit `connect_backend=managed` configuration remains supported. Use
`--backend managed` for legacy start/status/stop and connections. Runit
connections still require `--chatgpt`; the wrapper does not provision the
service or migrate its configuration. Lifecycle operations leave autostart
unchanged; enable/disable retain the new setting if the lifecycle action fails.

## Human CLI output

Wrapper diagnostics, configuration, updates, setup, package operations, and
service reports use compact sections, semantic colors, and narrow layouts.
`--wrapper-output auto|pretty|raw`, `CODEX_TERMUX_OUTPUT`, and literal `output`
configuration select presentation independently from color. Package tools accept
`--output`. Auto formats terminal streams; raw preserves service/log bytes.
JSON, completion scripts, internal protocols, and Codex streams stay literal.

Pretty logs remove incoming ANSI styling before highlighting timestamps and
severity, fixing visible `\x1b[...]` clutter. Consecutive logger/Codex timestamps,
including underscore timestamps, are retained. Other terminal controls remain
safe visible escapes. Message content, ordering, rotation, and interrupt cleanup
are preserved; no additional log recording is created.

Help, manual, Bash/Zsh completion, and configuration examples are aligned with
the implementation. Source archives include a repository skill, maintenance
guide, and output coverage matrix for future CLI changes.

## Upgrade and validation

After publication, use `codex-termux manage self-update` to update the wrapper,
or extract the source bundle and run `bash install.sh --source . --dry-run`
followed by the confirmed installation. `manage update` separately manages the
Codex npm runtime. Existing credentials, configuration, runtimes, and service
definitions are preserved.

The release contains 15 assets. `SHA256SUMS` covers 11 package payloads;
`RELEASE-SHA256SUMS` also covers the source archives and package manifest.
See `VALIDATION.md` in the source bundle for measured checks and platform limits.
Tests use owned roots and fake credentials; they do not establish live-account
health or Android remote pairing support. Publishing does not install this
version on the maintainer's device or change the running service.
