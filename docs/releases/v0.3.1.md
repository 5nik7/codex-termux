# codex-termux 0.3.1

Adds a recovery notice for logged MCP expired-token errors and an explicit
`codex-termux manage auth-check [--json]` command.

On eligible interactive launches, the wrapper checks newly appended diagnostic
records after Codex exits and suggests logout/login for `codex_apps` expiry.
It never runs those commands automatically. Saved-log checks do not establish
current authentication health. Logging must already be available; custom paths
use `auth_log` or `CODEX_TERMUX_AUTH_LOG`. Set `auth_notice=off` to opt out of
automatic notices.

Preserves the working DNS/proxy, authentication modes, terminal streams, signals,
exit statuses and help/completion fast paths. No startup network probe or new
runtime dependency. This release also includes the merged restrictive-umask
test-fixture correction in its source archives.

See `VALIDATION.md` for Linux fixture evidence and the native Termux checks
required before publication. The owner confirmed installation and healthy-session diagnostic-log
reading on native Termux with Codex CLI 0.155.1. Recognition of a
naturally occurring expired-token error remains unobserved.

The reminder requires an available plaintext Codex diagnostic log.
Explicitly setting top-level `log_dir` in Codex's config.toml enables
that log. Configure the wrapper's `auth_log` separately when using
a location other than its default.
