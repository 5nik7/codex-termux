# 0.4.1 — runit connection candidate

Adds an explicit connection backend for the already-installed `codex-remote`
termux-services service. Existing managed connections remain the default.

Use `CODEX_TERMUX_CONNECT_BACKEND=runit codex-termux connect --chatgpt`
for a one-shot connection. Set the literal `connect_backend=runit` in the
existing wrapper config for persistent selection. The default port is 4511;
`runit_port` / `CODEX_TERMUX_RUNIT_PORT` can override it.

Token location: `$HOME/.local/share/codex-remote/token`. The token and its parent
directory must be owner-only. Token file symlinks and nonregular files are
refused. The token is validated via an open descriptor and held in memory for
handshake verification and client launch. No token appears in client argv.

Resume/fork, explicit cwd, exit status and existing interrupt behavior are
preserved. The runit backend does not spawn a proxy, start/stop the service,
fall back to legacy state, or change credentials/configuration. It requires
`--chatgpt`; this selects client environment stripping, not a proof of server
account identity. External service/runtime version matching is the user's
responsibility. Ordinary launches and `manage server` retain existing behavior.

No service or live configuration changes are installed by this candidate.
Android app pairing remains unresolved and is not fixed by this patch.

Test the source wrapper on Termux before installing. Install with the existing
reviewed installer (`bash install.sh --source . --dry-run`, then the same command
without `--dry-run`). Version 0.4.1 avoids overwriting immutable 0.4.0 payloads.
Do not publish until native Termux acceptance is complete.
