# codex-termux v0.4.0

Local release candidate prepared September 27, 2026; uncommitted and unpublished.

## Opt-in managed WebSocket workaround

Start a detached app server and its native DNS/CONNECT proxy with
`manage server start --auth inherited|chatgpt [--port N]`. Inspect authenticated
connectivity with `manage server status`, attach with `connect [--chatgpt]`,
resume or fork through that connection, and explicitly end the server with
`manage server stop`. This is a workaround for the upstream Unix-socket daemon's
Termux `/tmp` limitation. **The upstream daemon is not repaired.** Ordinary
foreground launches and `run --no-daemon` keep their existing behavior.

Private per-CODEX_HOME state, capability-token WebSocket authentication, and
challenge-authenticated control prevent adoption or shutdown based only on a
stored PID or an unauthenticated HTTP response. Connections preserve arguments,
cwd, streams, exit status, and interrupt continuation. Server auth mode and the
selected runtime must match; updates do not silently restart active work.

The two reviewed fixes are included: malformed control MAC encodings are rejected
before constant-time comparison, and option scanning stops at Codex's own `--`
after the optional wrapper delimiter. Static Bash/Zsh completion, help, and the
manual cover the new commands. No model, approval, sandbox, or live auth/config
setting is rewritten. The external port 4500 remains reserved and untouched.

## Limits and recovery

A detached server can survive client exit and closure of its starting shell.
Android can still kill background processes under memory/battery pressure.
There is no force-stop/reboot survival guarantee, boot service, wake lock, or
automatic restart. A killed supervisor can leave its child alive; uncertain
state is retained and refused for owner review. Never delete active tokens/state
to bypass a possibly live instance. Use independent foreground `--no-daemon`
recovery while investigating. Automatic stale recovery, live custom-provider
switching, and coordinated multi-client conversation editing are not supported.
